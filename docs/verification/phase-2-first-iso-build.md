## Build Result

- Result: partial
- ISO created: yes
- ISO path: `artifacts/lotusos-amd64.iso`
- ISO size: `2406363136` bytes, approximately `2.3G`
- ISO metadata: `ISO 9660 CD-ROM filesystem data 'LotusOS amd64' (bootable)`
- El Torito boot info: BIOS boot image at `/boot/grub/grub_eltorito`

The first bootable ISO artifact was copied from the live-build workspace after `genisoimage` completed during the GRUB2 `iso-hybrid` build. That build then failed at the final `isohybrid` post-processing step because `isohybrid` is not installed on the WSL host.

A follow-up change switched live-build from `iso-hybrid` to plain `iso` to avoid the missing `isohybrid` host tool. A later clean wrapper build completed and copied a fresh ISO to `artifacts/lotusos-amd64.iso` at `2026-05-09 04:15:37 -0500`.

QEMU screenshot verification then showed SeaBIOS recognizing and attempting to boot from the DVD/CD, but no GRUB menu appeared after 90 seconds. Inspection found `binary/boot/grub/grub_eltorito` was only `2048` bytes, matching GRUB's `cdboot.img` stub without an appended `core.img`. The build script now repairs that GRUB2 El Torito image and rebuilds `binary.iso` before copying the artifact. The repaired build path has not yet produced a verified replacement ISO because the post-fix full rebuild timed out in the Codex tool window during package configuration.
